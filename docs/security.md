# Security and execution boundary

Submitted programs are hostile. The API never spawns or evaluates them locally. Only repository-owned reference programs are run locally in tests. Runtime requests use the documented [Judge0 API](https://ce.judge0.com/) and may include X-Auth-Token. Base64 transports preserve arbitrary program/input text. The adapter requests CPU, wall-clock, memory, process, file-size limits and network disabled; it bounds HTTP responses, stdout and diagnostics. This is **configuration intent, not verified sandbox isolation**.

Provision Judge0 on a dedicated execution host with current upstream security updates and reviewed OS/isolate configuration, inaccessible application secrets, no application-host Docker socket, restricted egress and authenticated private ingress. No privileged execution-engine containers are included in the app Compose file. Provider deployment, nonprivileged execution identities, filesystem isolation, network restrictions and escape resistance require operational verification before accepting hostile users. The adapter cannot prove these remotely.

Browser credentials use HttpOnly cookies with SameSite=Lax and configurable Secure. Set COOKIE_SECURE=true under HTTPS. State changes require X-CodeForge-CSRF: 1; an Origin header, when present, must exactly match FRONTEND_URL. The custom header prevents browser form submissions and cross-origin fetches through the restricted CORS policy. Non-browser callers must send the same header. Payment webhooks are exempt from CSRF and require signatures over the captured raw body. No configured webhook secret means no payment activation.

Passwords use the existing bcrypt library at cost 12; new passwords are capped at 72 UTF-8 bytes to avoid truncation. Access tokens expire in 15 minutes and are bound to active database sessions; refresh tokens expire in seven days, rotate once, carry unique IDs and are stored hashed. Logout revokes all sessions and refresh tokens for that user. Credential changes and reset revoke sessions. Reset tokens expire in one hour in Redis and are atomically consumed. Verification tokens expire after 24 hours from account creation. SMTP credentials and message bodies are not logged. TOTP secrets still use the inherited plaintext database field; encryption at rest and recovery codes remain future work.

Registration cannot select admin role. Bootstrap requires explicit unique credentials and refuses to modify an existing user. Every admin endpoint enforces server-side authorization. Profile stats never expose source, private profiles require owner/admin access, submission details require ownership/admin, and hidden test serialization removes echoable stdout/stderr and expected values.

Security headers, input bounds, request-size limits and rate limiting are implemented. Rate-limit counters are shared in Redis and fail closed on outages. A Redis lease semaphore bounds execution across workers. Dependency vulnerability remediation, real deployment validation, broader penetration testing and log redaction review remain necessary for production. Do not call the application production-secure based on these files.

The optional AI tutor keeps its key on the server and accepts authenticated, bounded requests with a per-user Redis quota. It checks published/premium problem access and submission ownership, selects public problem fields explicitly and filters sample results in SQL. Hidden test values, private reference programs and unpublished editorials are excluded before model calls. Provider errors are generic and do not log headers/source. The model has no tools and cannot submit code. The UI explains data sharing and includes code/results only by opt-in. Requests use store:false; consult provider/account retention settings before enabling. No live paid provider call was made in development checks.

Course mutations and imports are admin-only and audited. Import previews do not write; commits create drafts without overwrites and cannot specify isActive. External content requires provenance/permission details. Course reading changes require enrollment and apply only to the authenticated user. External resources use HTTPS URLs, and rendered Markdown does not enable raw HTML.
