# Google and GitHub sign-in

CodeForge now implements browser authorization-code flows for Google and GitHub, including PKCE, a browser-bound single-use state, provider-verified email, existing-account protection, session cookies, and two-factor authentication. The provider buttons are available only when real credentials and valid callback URLs are configured.

## Local setup

Keep backend `FRONTEND_URL` set to the actual address you use to open CodeForge (normally `http://localhost:3000`). Use the frontend's `/api` proxy so the login cookies belong to that address.

Create a **Web application** OAuth client in [Google Cloud](https://console.cloud.google.com/apis/credentials). Configure the consent screen, add your Google account as a test user while the app is in testing, and register this exact authorized redirect URI:

```text
http://localhost:3000/api/auth/google/callback
```

Create an [OAuth App in GitHub developer settings](https://github.com/settings/developers). Set Homepage URL to `http://localhost:3000` and Authorization callback URL to:

```text
http://localhost:3000/api/auth/github/callback
```

Put the credentials in the backend environment and restart the API:

```dotenv
FRONTEND_URL=http://localhost:3000
OAUTH_CALLBACK_BASE_URL=http://localhost:3000
COOKIE_SECURE=false
GOOGLE_CLIENT_ID=YOUR_ACTUAL_GOOGLE_CLIENT_ID
GOOGLE_CLIENT_SECRET=YOUR_ACTUAL_GOOGLE_CLIENT_SECRET
GITHUB_CLIENT_ID=YOUR_ACTUAL_GITHUB_CLIENT_ID
GITHUB_CLIENT_SECRET=YOUR_ACTUAL_GITHUB_CLIENT_SECRET
```

Replace every placeholder above with the value from the provider's dashboard. Never put client secrets in frontend variables or commit the environment file. Google/GitHub credentials cannot be generated by the application; the site owner must register its provider applications.

The legacy explicit `GOOGLE_CALLBACK_URL` and `GITHUB_CALLBACK_URL` variables are also supported; they must use those exact callback paths. If your provider applications already use `http://localhost:5000/api/auth/google/callback` and `http://localhost:5000/api/auth/github/callback`, keep those variables and ensure the backend is reachable on port 5000. Cookies on localhost are shared across ports. Do not change a working registered callback unless you also update the provider dashboard.

For deployment, use one public HTTPS hostname with `/api` routed to the backend, set `OAUTH_CALLBACK_BASE_URL` to that origin, set `COOKIE_SECURE=true`, and register its two callback URLs. The browser-bound state and session cookies require sign-in to start and finish on the same hostname. Callbacks never use the request Host header or a caller-supplied return URL.

## Expected behavior

- `GET /api/auth/providers` returns public enabled flags; it never returns credentials.
- Missing or obvious placeholder credentials disable the corresponding button.
- Google requires a verified email. GitHub reads the authenticated email API and requires a verified address; it prefers the verified primary email.
- A first sign-in creates an ordinary user and profile. Existing provider identities are found by their immutable Google subject/GitHub user ID.
- An email matching an existing unlinked account does not automatically merge accounts. Sign in using that account's original method, then open **Settings → Profile → Google and GitHub sign-in** and connect the provider. Linking requires the same authenticated browser session at the beginning and end of authorization. It cannot transfer a provider identity owned by another CodeForge user.
- Banned accounts cannot sign in. Accounts with two-factor authentication must supply their authenticator code before session cookies are issued.
- Callback failures return to the login page with an allowlisted error reason, without provider error bodies or secrets.

Authenticated integrations can call `GET /api/auth/connections` for connected flags, then navigate to `/api/auth/google?link=1` or `/api/auth/github?link=1`. Successful linking returns to `/settings?oauth=linked` and leaves the current account session in place.

Protocol reference: [Google OpenID Connect](https://developers.google.com/identity/protocols/oauth2/openid-connect), [GitHub OAuth authorization](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps), [GitHub authenticated email API](https://docs.github.com/en/rest/users/emails).

Mocked protocol/security tests run with `npm test -- --runTestsByPath tests/oauth.test.ts`. A real provider sign-in requires the owner-provided credentials, a correctly registered callback, and a browser smoke test.
